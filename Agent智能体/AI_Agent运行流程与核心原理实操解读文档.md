# AI Agent 运行流程与核心原理实操解读文档
### —— 以「Excel 报销文件自动汇总」办公案例全程拆解（WorkBuddy 智能办公 Agent）

> 适用对象：零基础办公人员
> 阅读方式：跟着案例一步步看，不需要任何代码和专业知识
> 配套工具：WorkBuddy 智能办公 Agent（本地办公自动化）

---

## 模块一：任务背景与案例介绍

### 1.1 为什么要讲这个案例

想象一下，你是公司的小张，月底到了，财务让你把桌面上的报销文件全部汇总一遍。你打开桌面一看：好家伙，30 多个 Excel 文件，有的叫"差旅报销 7月.xlsx"，有的叫"餐饮报销 7月.xls"，还有的散落在"发票整理"文件夹里。

如果人工来做，你的流程一般是：

1. 一个个打开文件，复制粘贴到一张总表里（30 次复制粘贴，手都要酸了）；
2. 发现有两笔报销长得一模一样，得手动删掉一条；
3. 发现有行金额是空的，得一个个去问当事人；
4. 最后用数据透视表按部门统计，再画个图表，折腾大半天。

**这就是 Agent 存在的意义**：把这种"重复、琐碎、有规矩可循"的办公活，交给一个不会累、不会看漏、不会手抖的智能助手去干。

### 1.2 案例任务原文（本次全程围绕它讲）

> **用户下发办公任务**：整理桌面近 30 天 Excel 报销文件，自动汇总所有报销数据、剔除重复数据、统计各部门报销总额，最终生成一份可视化汇总报表 + 问题数据清单，保存至桌面。

我们把这句话拆开看，里面其实藏着 5 个关键要素（Agent 接收任务时就要识别出来）：

| 要素 | 任务里的对应内容 |
|------|------------------|
| 处理对象 | 桌面上的 Excel 报销文件 |
| 时间范围 | 近 30 天 |
| 要干什么 | 汇总数据、剔除重复、统计各部门总额 |
| 交付成果 | 可视化汇总报表 + 问题数据清单 |
| 保存位置 | 桌面 |

### 1.3 和普通聊天 AI 先做个直观对比

- **普通聊天 AI**：你问它"我桌面有几个 Excel 文件？"——它只能回答"抱歉，我看不到你的电脑"。
- **WorkBuddy Agent**：你说"帮我汇总桌面的报销文件"，它能真正打开你的文件、合并数据、做统计、生成报表，并把文件保存到你的桌面。

一个只会"动嘴"，一个会"动手"。这就是整篇文档要讲清楚的核心。

## 模块二：Agent 完整 7 步落地执行流程

> 说明：Agent 干活不是"一口气做完"，而是按照 **接收任务 → 拆解规划 → 工具匹配 → 执行动作 → 结果观察 → 迭代纠错 → 自检交付** 这 7 步闭环推进。每一步，我们都用上面那个报销案例具体演示一遍。

---

### 第 1 步：接收任务（听懂人话，抓住关键信息）

**「Agent 在这一步做了什么」**

用户下达一句话任务后，Agent 不会马上动手，而是先"翻译"这句话：把模糊的自然语言，拆成一条条清楚、可执行的信息点——处理对象是谁、时间范围多大、要什么结果、放哪里。

结合案例，Agent 会把任务拆成 5 个信息点：

- 对象：桌面上的 Excel 报销文件
- 时间：近 30 天
- 动作一：汇总所有报销数据
- 动作二：剔除重复数据
- 动作三：统计各部门报销总额
- 输出：可视化汇总报表 + 问题数据清单，保存到桌面

**「为什么这么做」**

因为"模糊的任务"没法执行。如果连"文件在哪、要统计到哪天、结果放哪"都没确认，Agent 后面每一步都会做错。听懂人话、确认要素，是后面所有工作的地基。

**「解决什么问题」**

避免"瞎干"——比如用户说的是"报销文件"，Agent 不会去动桌面上的合同文件；用户说"近 30 天"，Agent 不会把三个月前的旧数据也统计进去。

> **【异常场景演示】信息不全时**
> 假设用户只说"帮我整理报销文件"，没说时间范围。Agent 不会乱猜，而是先向用户确认："您说的报销文件，是只统计近 30 天，还是全部？"——确认清楚再动手。这一问，就避免了"统计范围错了全盘返工"。

---

### 第 2 步：拆解规划（把大任务切成小任务清单）

**「Agent 在这一步做了什么」**

把"整理报销文件"这个大目标，拆成一张有序的"任务清单"（就像做饭先列菜单：洗菜 → 切菜 → 炒菜 → 装盘），并且排出先后顺序，因为后面几步要依赖前面几步的结果。

结合案例，Agent 规划的清单是这样的：

1. 扫描桌面及常用文件夹，找出所有 Excel 报销文件；
2. 判断哪些文件在"近 30 天"范围内；
3. 逐个读取每个文件里的报销数据；
4. 把 30 张表合并成一张总表；
5. 清洗数据：剔除重复、标记空值、统一格式；
6. 按部门汇总报销总额；
7. 生成可视化汇总报表和问题数据清单；
8. 保存到桌面，向用户交付。

**「为什么这么做」**

一口吃不成胖子。把大任务切成小块，每一块都能单独执行、单独检查，哪一步出了问题，立刻能定位到"是第几步坏了"，不用整个重来。

**「解决什么问题」**

让执行有"路线图"。用户不需要告诉 Agent 具体怎么操作，Agent 自己会规划：先找文件、再读数据、最后做报表，顺序乱不得——比如没读完数据就去统计，统计出来的肯定是错的。

---

### 第 3 步：工具匹配（从工具箱里选对的家伙什）

**「Agent 在这一步做了什么」**

Agent 的"手"不是凭空变出来的，它的每个动作都要落到具体的工具上。这一步，Agent 会对照第 2 步的任务清单，从它的工具库里选合适的工具——就像修水管的人，看到螺丝就拿起螺丝刀，看到漏水就拿起扳手。

结合案例，工具匹配是这样的：

| 任务清单里的活 | 匹配的工具 |
|----------------|------------|
| 找到桌面上的文件 | 文件扫描 / 目录浏览工具 |
| 判断时间范围 | 文件属性读取工具（看创建/修改时间） |
| 读取 Excel 数据 | Excel 表格读取工具 |
| 合并、去重、清洗 | 数据处理工具 |
| 按部门统计 | 分组统计工具 |
| 画可视化图表 | 图表生成工具 |
| 保存到桌面 | 文件保存 / 导出工具 |

**「为什么这么做」**

"工具"就是 Agent 干活的双手。聊天 AI 之所以不能碰你的文件，就是因为它没有这些工具；Agent 之所以能干活，就是因为它能调用这些工具，而且懂得"对症下药"——不同的活选不同的工具。

**「解决什么问题」**

保证每类操作都有"专业的手"来干。比如读表格就用表格工具、画图就用图表工具，而不是用一个万能工具笨拙地硬套。

> **【异常场景演示】文件格式混乱**
> 用户桌面上既有 `.xlsx`（新版 Excel），又有 `.xls`（旧版），可能还有 `.csv`（逗号分隔的表格）。Agent 识别到格式不统一后，不会只挑好读的读，而是**选择能兼容多种格式的读取方案**，或者分类型逐个处理，确保"一个都不能少"。如果某一种格式实在读不了，它会把该文件记入问题清单（到第 5 步会细讲），而不是悄悄跳过。

---

### 第 4 步：执行动作（真正上手干活）

**「Agent 在这一步做了什么」**

规划好了、工具也选好了，Agent 开始真刀真枪地执行：打开文件、读数据、合并、统计。这不是嘴上说"我可以帮你统计"，而是实实在在地在你的电脑上完成操作。

结合案例，执行过程大致是：

- 扫描桌面，找出所有报销类 Excel 文件，挨个确认修改时间是否在近 30 天内；
- 打开第一个文件，读取报销数据（日期、部门、报销人、金额、发票号……）；
- 打开第二个、第三个……直到所有符合条件的文件都读进来；
- 把 30 张表的内容合并成一张"总表"，共多少行、多少列，Agent 心里有数。

**「为什么这么做」**

Agent 的设计原则是"边干边看"，不是闷头一把梭。读完一个文件就确认一下"这个文件读成功没有"，相当于每走一步都抬头看一眼路，防止走偏。

**「解决什么问题」**

把"计划"变成"现实"。同时，因为边执行边记录，用户可以随时看到进度，也方便在后续步骤中检查每一批数据对不对。

> **【异常场景演示】表头不统一**
> 读到第 7 个文件时，Agent 发现这张表的列名和别的表不一样：其他表叫"报销金额"，这张表叫"金额（元）"。Agent 不会粗暴地照搬导致数据错位，而是**识别出这两个字段是同一个意思，做一次"字段对齐"**（把"金额（元）"映射到标准列"报销金额"）。这种"看懂差异、自动对齐"的能力，就是 Agent 比普通脚本聪明的地方。

---

### 第 5 步：结果观察（做完一步，检查一步）

**「Agent 在这一步做了什么」**

每完成一个动作，Agent 都要"回头看"结果：这一步干成了没有？数据对不对？有没有异常？观察结果就像照镜子——看看自己干得怎么样。

结合案例，合并完 30 个文件后，Agent 会自查：

- 30 个文件是不是全部读取成功？（有没有文件打不开？）
- 总表里一共多少行数据？和 30 个文件的记录数对得上吗？
- 有没有哪个文件读出来是空表？
- 各部门的数据大概分布是否合理？

**「为什么这么做」**

如果做完才看结果，错误可能已经悄悄扩散到后面每一步，返工成本极高。观察这一步，就是在"源头把关"，把问题拦在早期。

**「解决什么问题」**

及时发现"没读到的文件""读错的数据"，保证进入下一步的数据是完整、可信的。

> **【异常场景演示】文件损坏 / 加密打不开**
> 第 12 个文件打不开——可能是文件损坏，也可能设置了密码。Agent 不会因为这一个文件就中断整个任务，而是：
> 1. 把该文件记录到"问题数据清单"中，写明文件名称和打不开的原因；
> 2. 跳过它，继续处理剩下的文件；
> 3. 在最终交付时提醒用户："有 1 个文件未读取，请人工检查。"
>
> 这种"不中断、可继续、可交代"的处理方式，就是 Agent 干活的职业素养。

---

### 第 6 步：迭代纠错（发现问题 → 调整方案 → 重试）

**「Agent 在这一步做了什么」**

这是 Agent 的"灵魂步骤"。当观察发现数据有问题时，Agent 会**先想为什么，再决定怎么办，然后重新执行**——这个"发现问题 → 思考原因 → 换方案 → 再试"的循环，可能转好几圈，直到数据合格为止。这也是 Agent 名字里"自主"二字的真正含义。

结合案例，这里集中演示三个最常见的真实异常：

> **异常 1：数据重复**
> 总表里有两行报销，发票号、金额、部门完全一样——明显是同一笔报销录了两次。
> - Agent 怎么识别：按"发票号 + 金额 + 日期"等关键字段做比对，找出完全重复的记录；
> - Agent 怎么处理：剔除重复行，只保留一条，并记录"剔除了 N 条重复数据"；
> - 为什么这么做：不能闭着眼睛全删，也不能留着不管——留错数据，部门总额就虚高；全删可能删错。所以先识别、再剔除、后留痕。

> **异常 2：空值报错**
> 有一行的"报销金额"是空的。此时 Agent 面前有两条路：
> - 编一个数字填上去？——绝对不行！数据是假的，统计结果就全错了；
> - 正确做法：尝试从其他信息推断（比如备注里写了"金额 350 元"），能确认就补上并备注；确认不了，就把它标进"问题数据清单"，写清楚是哪一行、缺什么字段，交给用户人工确认。
>
> **这个"拿不准就不瞎猜"的原则，是办公数据场景里最重要的底线。**

> **异常 3：文件缺失**
> Agent 数了数，符合条件的文件只有 28 个，但按日期推算应该接近 30 个。
> - 先分析原因：可能是周末/节假日没人报销（正常），也可能是文件被误删或漏下载（异常）；
> - Agent 的处理：先按文件日期检查是否有合理缺口；发现确实缺了某几天的记录，就在问题清单里注明"疑似缺失，请确认"，而不是自己补一份假数据凑数。

**「为什么这么做」**

真实世界的文件永远是"脏"的——有重复、有空值、有缺失。Agent 的价值不在于"数据天生干净"，而在于**遇到脏数据时能自己发现问题、自己想办法解决、解决不了就明确告诉用户**。

**「解决什么问题」**

把"垃圾进、垃圾出"的风险降到最低。经过这一步，总表里的数据才是真正可以拿去统计的干净数据。

---

### 第 7 步：自检交付（交付前自己先验收）

**「Agent 在这一步做了什么」**

所有数据清洗、统计都完成后，Agent 不会直接甩给你两个文件就完事，而是先做一次"总验收"，确认无误后再交付，并向用户说明"我做了什么、有什么需要注意的"。

结合案例，交付前的自检包括：

- **数字交叉验证**：各部门总额加在一起，是否等于总表全部金额之和？对不上就说明还有问题，回去查；
- **报表检查**：生成的可视化报表能否正常打开、图表是否完整、部门名称是否齐全；
- **问题清单核对**：清单里的每个问题是否都写了"文件/行号 + 问题描述 + 建议处理方式"；
- **文件落位确认**：报表和问题清单是否确实保存到了桌面，文件名是否清晰（例如"报销汇总报表_2026-07.xlsx"）。

**「为什么这么做」**

交付质量代表 Agent 的"职业态度"。自己先验收一遍，能拦住最后关头发现的低级错误，避免用户拿到一份有硬伤的结果。

**「解决什么问题」**

让用户"拿到就能用、用着放心"，同时通过交付说明，把"哪些数据确定、哪些要人工复核"交代得明明白白。

## 模块三：Agent 核心运行原理总结

### 知识点 1：Agent 和普通聊天 AI 的本质区别

用一个比喻：**普通聊天 AI 是"顾问"，Agent 是"能干活的小助理"。**

- **顾问（普通聊天 AI）**：知识渊博，能跟你聊怎么汇总报销、教你怎么做表格，但它看不到你的电脑，也碰不了你的文件。它只"动嘴"。
- **小助理（Agent）**：同样聪明，但多了三样东西——**眼睛**（能看你的文件）、**手**（能操作工具）、**责任心**（干完会检查、会汇报）。它"动手"。

| 对比项 | 普通聊天 AI | WorkBuddy Agent |
|--------|-------------|------------------|
| 能不能看到/访问你本地的文件 | 不能 | 能（在授权范围内） |
| 能不能真正执行操作（读表、统计、生成文件） | 不能 | 能 |
| 能不能在断网/无云端环境下干活 | 一般不能 | 能（本地离线执行） |
| 遇到问题会不会自己想办法重试 | 不会，只会重新解释 | 会，自主思考后换方案重试 |
| 干完活有没有交付物（文件、报表） | 没有 | 有 |

一句话总结：**聊天 AI 回答"怎么做"，Agent 帮你"做成"。**

### 知识点 2：ReAct —— 思考 → 行动 → 迭代的核心运行逻辑

**ReAct** 不是高深术语，拆开看就两个词：

- **Re（Reasoning）思考**：这件事该怎么做？现在缺什么？刚才的结果对吗？
- **Act（Acting）行动**：调用工具，去执行、去操作。

关键在最后的"循环"——**思考 → 行动 → 观察结果 → 再思考 → 再行动**，转圈转到问题解决为止。

用本次案例演示一圈完整的 ReAct 循环：

```
思考（Re）  ：这张表的"金额（元）"和其他表的"报销金额"应该是同一个意思
    ↓
行动（Act） ：调用表格处理工具，做字段对齐，统一列名
    ↓
观察（Observe）：对齐后数据位置对了，金额列不再错位 → 通过，继续下一张表
    ↓
思考（Re）  ：哎，这张表里有两行发票号一模一样，可能是重复报销
    ↓
行动（Act） ：调用去重工具，按发票号比对，剔除重复行
    ↓
观察（Observe）：去重后总数减少了 3 条，和预判一致 → 通过
    ↓
……（循环继续，直到所有问题处理完）
```

**为什么说这是 Agent 的灵魂？** 因为普通脚本（写死的自动化程序）只会"照着剧本演"：剧本里没有"表头不统一"这一出，它就卡死或出错。而 Agent 在"行动之后还要观察、观察之后还能再思考"，所以面对剧本外的情况，它能自己改剧本、自己重演。**这就是"自主"二字的来源。**

### 知识点 3：WorkBuddy 办公 Agent 的专属能力特性

#### ① 本地文件授权（只在自己的地盘干活）

Agent 只能在用户明确授权的范围内访问文件（比如"只允许访问桌面和文档文件夹"），桌面以外的敏感目录，它不会碰，也碰不了。既方便，又守规矩。

#### ② 离线执行（数据不出电脑）

所有汇总、统计、制表都在本地完成，不需要把报销数据传到云端。对财务数据、发票信息这类敏感内容来说，**数据留在自己电脑里，是最安心的处理方式**。

#### ③ 办公工具联动（Office 全家桶协同）

WorkBuddy 不是只会读 Excel，而是能联动 Excel、Word、PPT、WPS 等常见办公工具。比如本次案例里：读 Excel 汇总 → 调图表能力出可视化报表 → 生成问题清单文档——一套流程跨多个办公软件接力完成，这正是办公场景的常态。

#### ④ 自动纠错复盘（越干越熟）

干活过程中遇到问题会自己调整方案（本案例第 6 步就是例子）；任务结束后还会"复盘"，记住这次的坑。下次遇到类似任务，它能避开已知问题，越干越顺。

#### ⚠️ 必须分清：办公 Agent 与代码 Agent 的区别

很多朋友容易混淆这两类 Agent，这里明确区分：

| 对比项 | 代码类 Agent（如 Trae） | 办公类 Agent（如 WorkBuddy） |
|--------|--------------------------|-------------------------------|
| 服务对象 | 程序员 | 办公人员 |
| 主要能力 | 写代码、改代码、调试程序 | 操作办公软件、处理文档和表格 |
| 交互方式 | 面向代码仓库和开发环境 | 面向本地文件和 Office 工具 |
| 典型任务 | "帮我写一个登录接口" | "帮我汇总桌面报销文件" |
| 要不要会编程 | 使用者最好懂开发 | 使用者完全不需要懂代码 |

一句话：**Trae 帮你"写程序"，WorkBuddy 帮你"干办公活"。** 两者是 Agent 家族里的不同岗位，别混为一谈。

## 模块四：WorkBuddy Agent 实操核心优势与避坑要点

### 4.1 实操核心优势

1. **解放重复劳动**：复制粘贴、手工去重、手动透视这类重复活，交给 Agent，半小时变 3 分钟；
2. **过程全程留痕**：每一步做了什么、删了几条重复、标记了哪些问题，都有记录可查，出了问题能追溯；
3. **隐私安全有保障**：本地离线处理，敏感财务数据不出电脑；
4. **出错能自我修复**：遇到脏数据、异常文件，自己想办法解决或明确标注，不会"装没看见"。

### 4.2 避坑要点（实操经验）

1. **任务描述要具体**：时间范围、文件位置、输出要求尽量一次说清。比如"近 30 天""保存到桌面"这种信息，说得越清楚，Agent 干得越准；
2. **原始文件先备份**：涉及合并、清理、去重之前，先让 Agent 复制一份原始文件到备份文件夹，防止误操作后无法还原；
3. **授权范围要核对**：只授予任务需要的文件夹权限，不需要的目录不放行，这是数据安全的基本盘；
4. **涉及金额必须人工抽验**：Agent 统计的结果可以先抽查几笔，和原始发票核对一下。Agent 再聪明，关键数据也要"眼见为实"；
5. **拿不准的数据，宁可进问题清单，不让 Agent 瞎猜**：缺失金额、疑似重复这类情况，让 Agent 标出来给你确认，而不是自己编个数字；
6. **大任务建议分步确认**：文件特别多（比如上百个）时，可以先让 Agent 跑"扫描 + 读取"，确认文件齐了再继续统计，避免最后才发现漏文件。

## 落地总结：极简口诀

把 Agent 的运行逻辑浓缩成一段口诀，日常下发任务时照着默念就行：

> **一听二拆三选具，四干五看六纠错，七检交付才收工，闭环跑完活干成。**
>
> - 一听：先听懂任务，关键要素问清楚；
> - 二拆：大任务切成小步骤，排好顺序；
> - 三选具：按步骤选对工具；
> - 四干：真正动手执行；
> - 五看：做完一步看一步结果；
> - 六纠错：发现问题，思考换法，重新再试；
> - 七检：交付前自己验收一遍，再向用户交代。

记住一句话压轴：**普通聊天 AI 只会"说"，Agent 会"想、干、查、改、交"。把重复的办公活交给它，你把把关就行。**
